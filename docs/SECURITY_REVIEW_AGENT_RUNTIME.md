# Agent runtime security review

This review records the findings from the pre-hardening runtime foundation and the fixes now in place. The initial observations refer to the runtime source before this hardening pass; current implementation references follow each finding.

| Finding | Pre-hardening evidence | Risk | Fix and verification |
|---|---|---|---|
| A1: approval spoofing | `alpha_core/agent/runtime.py` (pre-hardening lines 36–45) accepted `approved_call_ids` from the caller and treated a matching call ID as approval. | Any caller able to invoke the runtime could supply a call ID and bypass human review. | Removed the argument and callback trust paths. Dispatch now consumes a matching persisted approval in `alpha_core/agent/approvals.py:250` and rechecks policy in `alpha_core/agent/runtime.py:184`. Covered by `tests/test_agent_runtime.py:202`. |
| A2: no approval ledger | The original `alpha_core/agent/trace.py` schema (pre-hardening lines 52–78) stored runs and steps only; approvals existed only as a runtime boolean. | No requester/approver identity, expiry, replay protection, or durable decision record. | Added a SQLite approval table and `request_approval`, `approve`, `reject`, `expire_stale`, and `consume` in `alpha_core/agent/approvals.py:19`. Tests cover role, self-approval, workspace, expiry, rejection, and replay at `tests/test_agent_runtime.py:202` and `tests/test_agent_runtime.py:428`. |
| A3: mutable execution inputs | `alpha_core/agent/models.py` used frozen Pydantic models around mutable nested dictionaries/lists; the old runtime hashed ordinary serialization and accepted a caller-supplied plan on resume. | A caller could mutate arguments after validation or change the resumed plan without matching the approval. | Plans use tuple steps and are deep-copied/canonicalized in `alpha_core/agent/runtime.py:345` and `alpha_core/agent/runtime.py:351`; resume accepts only a run ID and loads the stored plan. Registry specs are copied at registration in `alpha_core/agent/registry.py:44`. Covered by `tests/test_agent_runtime.py:320` and `tests/test_agent_runtime.py:357`. |
| A4: duplicate execution and unsafe retries | The old runtime had no atomic run/step claim, run lock, or step idempotency context; it retried `RetryableToolError` regardless of side effect (`runtime.py`, pre-hardening lines 108–143). | Concurrent requests or retries could duplicate writes. | Added a scoped request idempotency key, per-run lock, SQLite compare-and-set claims at `alpha_core/agent/trace.py:317` and `alpha_core/agent/trace.py:327`, and stable tool context at `alpha_core/agent/models.py:150`. Automatic retry is read-only in `alpha_core/agent/runtime.py:222`. Tests at `tests/test_agent_runtime.py:372` and `tests/test_agent_runtime.py:408`. |
| A5: lifecycle and timeout handling | Original states omitted `planned`, and tool timeouts were persisted as a lowercase implementation string (`runtime.py`, pre-hardening line 134). | Lifecycle steps were harder to audit and timeout status was not a stable error code. | Added explicit run/step transitions in `alpha_core/agent/trace.py:13` and records `TIMEOUT` in `alpha_core/agent/runtime.py:220`. Cancellation and invalid transitions are covered at `tests/test_agent_runtime.py:180` and `tests/test_agent_runtime.py:524`. |
| A6: unsafe/unbounded trace data | Original `alpha_core/agent/trace.py` stored raw JSON arguments/results and had no correlation IDs, per-run byte cap, or purge operation. | Secrets or oversized results could remain in traces indefinitely. | Added key redaction, sensitive-plan rejection, field/run limits, correlation IDs, error-code validation, and retention purge at `alpha_core/agent/trace.py:408`, `alpha_core/agent/trace.py:451`, and `alpha_core/agent/trace.py:459`. Tests at `tests/test_agent_runtime.py:462`, `tests/test_agent_runtime.py:489`, and `tests/test_agent_runtime.py:513`. |
| A7: unscoped trace access | Original public `get_run(run_id)` and `list_steps(run_id)` methods in `trace.py` queried by run ID alone. | A caller with a run ID could inspect or interfere with another user's data. | Public reads now require identity and enforce workspace, owner, and admin scope in `alpha_core/agent/trace.py:231`, `alpha_core/agent/trace.py:279`, and `alpha_core/agent/trace.py:443`. Cancellation and approvals perform the same workspace check. Covered by `tests/test_agent_runtime.py:427`. |
| A8: missing adversarial coverage | The initial suite had 13 runtime tests and did not exercise persisted approvals, mutation, replay, isolation, redaction, retention, or duplicate calls. | Security regressions could pass the normal workflow tests. | Expanded `tests/test_agent_runtime.py` to exercise these cases, plus LLM-off, timeout, cancellation, schema failures, output caps, migration, and illegal states. Current runtime suite: 23 passing tests. |

## Shared session identity

The Knowledge Assistant's signed-cookie serialization is now shared through `alpha_core/auth.py:14`; the application still resolves the signed subject to an active user row in `tools/enterprise-knowledge-assistant/app/main.py:188`. Existing login, role, ACL, and authentication tests passed after the refactor. Any future Hub route must use that server-resolved principal to build the runtime identity; request bodies and headers are not identity sources.

## Remaining limits

The runtime is a local SQLite implementation, not a distributed executor. SQLite is not encrypted at rest. Tool handlers must implement the provided idempotency key for side effects that can outlive a process crash. A web API must add CSRF protection and rate limiting before exposing approval or cancellation actions. No production deployment claim is made.
