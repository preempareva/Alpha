# Blueprint execution roadmap

The supplied handbook explicitly recommends a focused build sequence rather than 13 shallow demos. This repository completes the local MVP for Project 1 and records the remaining sequence here. A project is not marked complete until its own end-to-end release gate, measured evaluation, and demo evidence exist.

| Sequence | Blueprint project | Status |
|---|---|---|
| Foundation | Shared Python/API/data-contract baseline | Applied in this project |
| 1 | Knowledge Assistant | Local prototype implemented; external identity and deployment gates remain |
| 2 | Customer Churn Prediction | MVP implemented: `../customer-churn-prediction/` |
| 3 | BI Analyst Workflow | MVP implemented: `../multi-agent-business-intelligence/` |
| 4 | Helpdesk Triage | MVP implemented: `../ai-it-helpdesk-assistant/` |
| 5 | Customer Sentiment Insights | MVP implemented: `../customer-sentiment-intelligence/` |
| 6 | Inventory Control Tower | Merged demand and replenishment workflow: `../inventory-optimization-agent/` |
| Optional | Remaining seven specialist ideas | MVP prototypes added; see [`../AI_PROJECT_BLUEPRINT_ROADMAP.md`](../AI_PROJECT_BLUEPRINT_ROADMAP.md) |

Project 1 still needs a verified identity provider, an authorized 30–100 document corpus, broader labelled retrieval evaluation, operational monitoring, and a reviewed deployment before it is suitable for organizational data. The synthetic demo and local automated checks do not satisfy those real-world gates.
